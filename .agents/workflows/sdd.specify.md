# SDD Phase 0: 仕様策定ワークフロー (`/sdd.specify`)
<!-- .agents/workflows/sdd.specify.md -->

ユーザーからの新規要件・魔獣生成・ルール追加の要望を受け、`.specify/specs/[機能・魔獣名].spec.md` を起草するワークフロー。

## 1. 前提条件 (Prerequisites)
- 関連資料（`constitution.md`, `project-context.md`, `world/*.md`, `doc/questions_and_answers.md`）の事前全走査。

## 2. 実行手順 (Execution Steps)
1. **原典・神話伝承調査（古典文献タスクフォース / シュルツ担当）**:
   - 古代オリエント・古典ギリシャ/ローマ・中世寓意譚（ベスティアリ）・世界民俗学の文献を網羅調査し、文献名・章節・原語・具体的エピソード（能力・外見・弱点・副産物・商業逸話等）を抽出。仕様書に「第0章: 原典・神話伝承考証」として必着。
2. **原典発祥地マッピング ＆ 一次生息地特定（地誌班 / 陣内担当）**:
   - 伝承および原種生物の地理的発祥地域（欧州、地中海、中東、極地、深海等）を必ず【本来の一次野生生息地（Primary Habitat）】として特定。
   - 日本国内での出現については安易な自生を禁じ、【外来輸入・メガコーポ施設飼育・密輸個体】等の国際流通リアリズムを明示的に判定・記述。
3. **外部科学リサーチ（生物・弾道グラウンディング / 鷹司・クリスティナ担当）**:
   - 原種生物データ（骨格・咬合力・感染症）、銃火器弾道データ（初速・運動エネルギーJ）、実在地理・法規データを調査。
4. **仕様書の起草**:
   - テンプレート（`.specify/templates/spec_template.md`）に基づき、第0章から始まる `.specify/specs/[名称].spec.md` を作成。
5. **5専門部署事前審査 ＆ 方向性・生態モデル合意**:
   - 生物・地理・歴史伝承・魔導理論・憲章監査の全観点から整合性を検証し、方向性選択肢（A/B/C/X ※必ずアルファベットに統一）を提示。
6. **★ 和名複数選択肢の提示と決定（和名選定ステップ）**:
   - 方向性合意を受領後、標準和名命名規約（形態型、環境型、季節型、伝承型等）に基づく**複数の標準和名候補（A/B/C/D... ※必ずアルファベットに統一）を提示し、ユーザーに選択・決定してもらう**。
7. **機械的仕様バリデータ実行 ＆ 承認トークン発行**:
   - `.\engine\sdd\run_gate.ps1 -Id <id> -Gate 1` を実行し、100% PASS を確認。
   - ユーザーから Gate 1 承認を受領後、`.\engine\sdd\run_gate.ps1 -Id <id> -Step gate1 -Approve -Notes "..."` で承認トークン（`gate1.json`）を発行。

## 3. 完了条件 (Done Definition)
- 第0章、原典発祥地マッピング、外部科学データ、和名複数選択肢決定を含む仕様書が確定し、`run_gate.ps1 -Gate 1` が 100% PASS し、`.specify/approvals/<id>_gate1.json` が発行されていること。

## 4. 次フェーズへの移行 (Next Phase Handoff)
- Gate 1 承認トークン発行確認後、**Phase 2: 実装計画策定 (`/sdd.plan`)** へ移行する（※トークンが無い場合は物理ブロック）。
