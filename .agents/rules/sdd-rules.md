# 仕様書駆動開発 (SDD) 厳守行動規範
<!-- .agents/rules/sdd-rules.md -->

本ドキュメントは、AI（Antigravity / Gemini）が本リポジトリで作業を行う際の「仕様書駆動開発（Specification-Driven Development: SDD）」の絶対行動規範を定めたものです。

---

## 1. SDD サイクルと品質ゲート（必須ワークフロー）

AIは新規設定・魔獣・ルール・コードを直接作成する「バイブ・コーディング」を厳禁とし、必ず以下のSDDサイクルを順守しなければならない：

```
[1. Specify] ── 仕様書（.specify/specs/*.md）の起草（要件・科学グラウンディング・整合性チェック）
      ▼
[2. Clarify] ── 矛盾・曖昧さの検知時に即時停止（HALT）し、選択肢付きですり合わせ
      ▼
[3. Plan] ── 実装計画書（.specify/plans/*.md）の作成（ファイル変更一覧・品質ゲート）
      ▼
[4. Tasks] ── タスク一覧（.specify/tasks/*.md）への分解
      ▼
[5. Analyze] ── 憲章（constitution.md）および既存全ドキュメントとの整合性クロスチェック
      ▼
[6. Implement] ── ユーザー承認後に実装（world/*.md, creatures/*.md 等の執筆・編集）
      ▼
[7. Audit] ── 監査ログ（doc/audit.log）および Q&A（doc/questions_and_answers.md）への永続記録
```

---

## 2. 矛盾検知時の即時停止（HALT）とすり合わせプロトコル（絶対遵守）

### 2.1 ブロック（HALT）の発動条件
以下の事象が検知された場合、AIは**一切の自己判断・勝手な辻褄合わせを禁止し、即座に作業を停止してユーザーにブロックを報告すること**：
1. 憲章（`constitution.md` / `AGENTS.md`）の絶対法則（26年時間軸、科学と魔術の完全並行、兵器バランス等）と矛盾する要求・提案。
2. 過去に合意・確定したQ&A（`doc/questions_and_answers.md`）と衝突する内容。
3. 既存ドキュメントの重要設定が意図せず削除・短縮・消失する恐れがある場合。
4. 要求仕様に致命的な曖昧さや複数の解釈が存在する場合。

### 2.2 すり合わせ提示フォーマット
作業を停止した上で、以下の4要素を明確に出力して指示を仰ぐこと：
- **① 検出箇所**: 該当ファイルパスと既存記述
- **② 問題点・衝突内容**: 何がどのように衝突しているかの解説
- **③ 解決案の選択肢**: `A)`, `B)`, `C)` ... および末尾の `自由回答 X)`
- **④ 回答フォーマット例**: `[Q: A]` または `[Q: B, X: ○○]`

## 3. 現実科学グラウンディング（外部リサーチ裏付け）の義務

魔獣・武器・地理・法規を定義する際は、必ず事前にWeb検索ツール（`search_web`）を用いて、現実世界の解剖学・弾道学・都市インフラ・ジビエ法規の数値を調査し、それを土台として仕様書に明記すること。
